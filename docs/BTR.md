# PiliPlus BTR 1.0.0

本版本基于 PiliPlus 2.1.6.2，应用版本为 `1.0.0+1`。
`main` 和 `v1.0.0` 是本次发布的两个分支名称。

这是在用户提供的 PiliPlus 源码上新增的 Dart 下载模块，参考
[Bilibili-thread-ripper](https://github.com/MrTangLuyao/Bilibili-thread-ripper)
的多 CDN / 多 Range 思路，未直接复制其 JS 实现。PiliPlus 的 GPL-3.0
许可证保持不变。这是第一版接入，不等同于上游 BTR 的全部功能。

## 使用

在视频播放页右上角「⋮ 更多设置 → BTR 加速设置」可直接设置开关、并发上限和
节点模式，以及「全接管（增强调度）/兼容模式」和「自动线程数」。面板显示当前
连接、前方缓冲秒数、缓存大小和慢块补救次数。
点击「应用」后从当前进度重新加载，保留播放/暂停状态，并保存为默认值。
正在初始化的视频会保存设置，在下次加载时生效；离线视频不显示该入口。
全局「我的 → 设置 → 音视频设置」仍可设置这些默认值。默认关闭，
默认并发上限 8、大陆节点模式。设置在下次加载视频或切换清晰度时生效。
关闭后重新加载视频即可恢复播放器原有下载路径。

- 原始节点：对 PiliPlus 原本选择的节点并发请求，可单独验证并发收益。
- 大陆/海外节点：在可迁移的 `/upgcxcode/` 地址上保留签名并替换 CDN 主机，
  同时保留 PiliPlus 选出的原始地址作回退。不适用的 PCDN 路径不替换。
- 仅处理已取得播放地址的点播 `.m4s` / `.mp4` 音视频，其他地址直接交给播放器。
  直播、离线视频、EDL 多段视频和投屏地址保持原有路径。
- 现有「CDN 设置」决定模块收到的原始地址；BTR 节点模式决定额外候选节点。
  BTR 没有新增账号、会员或地区权限获取逻辑。

## 结构

`PlPlayerController._createVideoController` 在打开媒体前创建 BTR 会话，
将播放用的地址转换成 `127.0.0.1` 上的随机 token 地址。控制器的原始
`dataSource` 与页面 `videoUrl/audioUrl` 不变，供投屏和其他功能使用。

`lib/services/btr/` 是无 Flutter 和第三方包依赖的独立模块：

- `range.dart`：包含式字节范围、后缀范围、Content-Range 校验。
- `cdn_pool.dart`：受限的 CDN 候选构造、速度记录、节点分配和失败降级。
- `proxy.dart`：回环 HTTP 服务、音视频共享限并发及优先队列、连接池、
  分块下载与顺序输出、慢块补救、缓存和滚动预取、原始请求透传、会话清理。
- `adaptive.dart`：播放缓冲反馈的并发控制，带冷却时间与用户指定上限。

先对几个候选节点并行请求 `bytes=0-0`，采用最先成功的媒体长度探测结果，
取消其他探测，并优先用该节点获取起播前缀。网络操作设硬截止时间，
不只依赖关闭 HttpClient 来结束无响应的请求。兼容模式以 128 KiB 分块滚动补充
下载队列（最多 16 个在途/待交付块）；不再等待整批完成后才启动下一批。
起播或拖动请求先获取并立即输出 16 KiB 的已校验前缀，再调度后续批量下载。
每块必须得到匹配的 HTTP 206、Content-Range、总长度与实际字节数。
窗口中的块可乱序完成，但只按字节顺序写给 mpv；每个可输出的连续块立即
刷新到播放器，不等待窗口中所有块完成。BTR 路径的 mpv 网络等待时间设为
30 秒，上游下载超时和重试仍由模块控制，关闭 BTR 的路径保持原有设置。

探测失败或第一窗口失败可回退到原始 HTTP 请求；已发送数据后若无法恢复，
关闭不完整响应，让播放器按原有机制重试，不能拼入未经校验的数据。
没有可用节点时不保证播放成功。签名过期仍依赖 PiliPlus 原有重新获取播放地址流程。

会话在切换媒体时清理，播放器最终销毁时关闭本地服务。
本地服务只绑定回环接口、随机端口，随机 token 仅映射预注册媒体，
不接受通过 HTTP 参数指定任意上游地址。上游请求不传账号 Cookie。
Android 配置仅允许回环地址的明文 HTTP，不放宽远程 HTTPS 证书检查。

## 两种手机端工作模式

共同部分：按节点复用 HTTP 连接，避免每个小块都重新建立 TCP/TLS；只有正在
使用的响应流会在取消时关闭，不会破坏同一节点的其他请求。节点选择考虑历史吞吐
和当前负载，保留少量探索请求。支持手动上限及基于缓冲的自动并发调整。

- **兼容模式**：按 mpv 发出的 Range 请求并发下载、滚动补充队列；保留原有
  播放器缓冲设置，不启用 BTR 的跨请求缓存、主动预取或慢块竞速。
- **全接管（增强调度）**：BTR 管理媒体下载的共享缓存和滚动预取。以 256 KiB
  对齐块合并重复读取，视频最多缓存 8 MiB、音频最多 2 MiB（含在途块槽位限制）。
  下载即将交付的块和音频优先；为慢块补救保留一个连接槽位。只有当前需要的块
  明显拖慢时才在另一节点补发，采用首先通过范围/长度校验的结果并取消另一份。
  同时接入播放器缓冲反馈、自动并发和拖动取消。mpv 前向缓存上限设为 64 MiB、
  缓冲目标 60 秒、回看缓存 8 MiB，更早恢复补充缓冲。

手机端的「全接管」是增强下载调度，并非网页 MediaSource 实现的原样移植；
mpv 继续负责解码、媒体时间线和播放。缓存为内存缓存，不保存完整视频。
自动并发不突破用户上限，缓冲不足时上调，缓冲充足时逐步回落，暂停时不主动上调。
部分块断点续传、基于 SIDX 的精确播放截止时间、播放地址自动刷新仍未移植。

## 验证

不需要 Flutter 或 `pub get` 的模拟 CDN 集成测试：

```powershell
dart tool/btr_proxy_test.dart
dart analyze lib/services/btr tool/btr_proxy_test.dart
```

覆盖字节一致性、乱序完成、音视频共享并发、完整/开放/后缀 Range、HEAD、416、
错误范围、总长度变化、403、无 Range 透传、超时换节点和会话注销。
另覆盖「尾部分块缓慢但起播前缀应及时到达」，避免重新出现批量等待与 mpv
默认 5 秒网络超时冲突的问题。
同时覆盖无响应节点的并行起播探测与硬超时，确保探测胜出节点直接服务起播前缀。
增强调度专项覆盖连接复用、12 MiB 媒体的缓存上限、缓存命中避免回源、
慢块补救和败方取消、全接管模式的音视频并发上限、拖动清理与自动并发反馈。

完整客户端需要项目指定的 Flutter 3.47.7（Dart >=3.13.0）和依赖。
机器相关配置保存在不提交 Git 的本地环境文件中。可通过 `BTR_BUILD_ENV`
指定该文件，默认读取工作区的 `.tooling/build-env.ps1`。在其中配置
Flutter、Pub/Gradle 缓存、Android SDK、JDK 及临时目录，并将相关工具加入 PATH。
建议将工具与缓存放在非系统盘，具体目录仅保存在本地配置中。
构建脚本自动加载配置，再从 PATH 查找 Flutter 和 ADB。

使用现成的构建/安装脚本：

```powershell
.\tool\build-android.ps1
.\tool\build-android.ps1 -Install -Device YOUR_DEVICE_SERIAL
```
